# Выявленные уязвимости и баги

Дата анализа: 2026-05-13

---

## 🔴 Критично

### 1. Prompt Injection ✅ исправлено
**Файл:** `app.py`  
**Описание:** Поле `goal` вставляется напрямую в промпт GigaChat без санитизации. Пользователь может написать инструкцию внутри поля и заставить ИИ проигнорировать системный промпт.  
**Что пофиксили:** `goal` прогоняется через `" ".join(goal.strip().split())` при сохранении в session_state — схлопывает все переносы строк и лишние пробелы в один пробел. Дополнительно стоит `max_chars=100`.

## 🟠 Серьёзно

### 2. SSL-верификация отключена
**Файл:** `app.py`, строка 147  
**Описание:** `verify_ssl_certs=False` в GigaChat-клиенте отключает проверку сертификатов. Открывает MITM-атаку — трафик с ключом API и данными пользователей можно перехватить.  
**Что фиксить:** Добавить корневой сертификат Минцифры / СберКорень и указать путь к нему, вместо отключения верификации.

### 3. Нет rate limiting
**Файл:** `app.py`, строка 61  
**Описание:** Каждый сабмит формы бесконтрольно вызывает GigaChat API. Можно спамить запросами и выжечь квоту или бюджет.  
**Что фиксить:** Добавить `st.session_state`-счётчик запросов или cooldown между отправками.

## 🟡 Средне

### 4. HTTP-статус Stepik не проверяется ✅ исправлено
**Файл:** `stepik.py`  
**Описание:** После запроса к Stepik сразу вызывался `.json()` без проверки статуса. При 429 / 500 код пытался распарсить ошибку как список курсов.  
**Что пофиксили:** Добавили `response.raise_for_status()` перед `.json()` — при любом HTTP-ошибочном статусе бросает исключение, которое ловит `except Exception` и возвращает `[]`.

### 5. Нет ограничения длины поля goal ✅ исправлено
**Файл:** `app.py`  
**Описание:** `st.text_input` без `max_chars`. Пользователь мог вставить огромный текст → раздутый промпт → лишние расходы API.  
**Что пофиксили:** Добавили `max_chars=100`.

### 6. Нет валидации GIGACHAT_AUTH_KEY ✅ исправлено
**Файл:** `app.py`  
**Описание:** Если `.env` не создан или ключ пустой — приложение падало с криптичной ошибкой GigaChat.  
**Что пофиксили:** Добавили проверку `os.getenv("GIGACHAT_AUTH_KEY")` сразу при старте — при отсутствии ключа показывается понятная ошибка и `st.stop()`.

## 🔵 Мелкое

### 7. Молчаливый except в search_stepik_courses
**Файл:** `app.py`, строки 28–29  
**Описание:** `except Exception: return []` глотает все ошибки Stepik (сеть, парсинг, timeout). При отладке непонятно, что пошло не так.  
**Что фиксить:** Как минимум логировать ошибку: `except Exception as e: st.warning(...)` или `print(e)`.

### 8. Параметр page_size не документирован Stepik API
**Файл:** `app.py`, строка 22  
**Описание:** `page_size: 50` передаётся в Stepik API, но этот параметр не задокументирован в публичном API и может просто игнорироваться.  
**Что фиксить:** Проверить реальный лимит Stepik API и использовать корректный параметр.

## Баги, выявленные при тестировании

### 9. Пробел в поле goal проходит валидацию ✅ исправлено
**Файл:** `app.py`, строка 62  
**Воспроизведение:** Ввести пробел (или несколько пробелов) в поле "Чему хочешь научиться?" и нажать кнопку.  
**Что происходит:** Проверка `if not goal:` не ловит пробел — `" "` в Python truthy. В итоге план обучения не генерируется (GigaChat отказывается или ведёт себя непредсказуемо), а Stepik возвращает случайные нерелевантные курсы по запросу `" "`.  
**Что фиксить:** Заменить `if not goal:` на `if not goal.strip():`

### 10. Ввод только цифр в поле goal проходит валидацию ✅ исправлено
**Файл:** `app.py`, строка 62  
**Воспроизведение:** Ввести только цифры (например `123`, `999`) в поле "Чему хочешь научиться?" и нажать кнопку.  
**Что происходит:** Валидация пропускает ввод, GigaChat строит трек обучения по бессмысленному запросу вместо отказа.  
**Что фиксить:** Добавить проверку `any(c.isalpha() for c in goal)` — поле должно содержать хотя бы одну букву (русскую или латинскую).

### 11. Краш при RateLimitError от GigaChat ✅ исправлено
**Файл:** `app.py`, строка 146  
**Воспроизведение:** Отправить несколько запросов подряд быстро.  
**Что происходит:** GigaChat возвращает 429 RateLimitError, приложение крашится с полным трейсбеком вместо понятного сообщения.  
**Что пофиксили:** Обернули вызов GigaChat в `try-except`, при RateLimitError показываем: "Слишком много запросов к ИИ. Подожди немного и попробуй снова."

### 12. Промпт некорректно отклонял реальные профессии ✅ исправлено
**Файл:** `app.py`, строка 76  
**Воспроизведение:** Ввести "стать пилотом формулы 1" или другую реальную, но амбициозную профессию.  
**Что происходит:** GigaChat отказывался строить трек, приравнивая реальные профессии к невозможным целям ("стать суперменом").  
**Что пофиксили:** Переписали инструкцию в промпте — теперь отказ только для физически невозможных и абстрактных целей. Реальные профессии всегда принимаются.

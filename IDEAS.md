# 💡 Идеи для реализации

## Источники контента

- **Онлайн-школы (Skillbox, GeekBrains, Яндекс Практикум)** — захардкодить топ-10 курсов по популярным темам с ценами. API у них закрытый, обновлять вручную раз в месяц.
- **Habr** — парсинг статей по тегам. API закрытый, но страницы статичные — несложно реализовать.
- **Rutube** — ссылка на поиск реализована. API geo-блокирует запросы с нероссийских IP (Streamlit Cloud), поэтому показывается ссылка на поиск вместо результатов.
- **VK Видео** — стабильно в РФ, но образовательного контента мало. YouTube заблокирован в большинстве городов РФ — не использовать.

## Функциональность

- **Диагностика знаний** ✅ реализовано — 3-шаговый флоу (ввод → тест → результат). GigaChat генерирует 4 вопроса по теме, уровень определяется детерминированной формулой по очкам. Ответы диагностики передаются в промпт трека для персонализации.
- **Фильтрация и сортировка курсов Stepik** ✅ реализовано — фильтр по языку (только русские), фильтр по бюджету, сортировка по `learners_count` убыванием. Рейтинг курсов через публичный API недоступен без авторизации (`review-summaries` требует токена). Сортировка по уровню сложности нативно невозможна (`difficulty: null` у большинства курсов).
- **Практические задания** — в каждом этапе трека добавить одно конкретное задание от ИИ.
- **Проверка заданий** — пользователь вставляет своё решение, GigaChat проверяет и даёт обратную связь.
- **Сохранение прогресса** — пользователь отмечает пройденные этапы и возвращается к треку.

## Формула полезности источников

Идея: вместо простой сортировки по `learners_count` — скоринг курсов по нескольким факторам.

### Вариант A — взвешенная формула вручную
```python
score = learners_count * 0.7 + is_popular * 1000 + lessons_count * 0.3
```
Быстро, не требует данных. Технически не регрессия — захардкоженные веса. Улучшает текущую сортировку, но субъективно.

### Вариант B — настоящая регрессия (долгосрочно)
Пользователь оценивает курсы после прохождения (1–5 звёзд). Оценки накапливаются в БД. Через время обучается регрессионная модель на реальных данных. Требует: личный кабинет + хранилище + достаточный объём оценок.

### Вариант C — оставить learners_count (текущее решение)
Популярность как прокси качества. Простое, работает, не требует поддержки.

## Тропинка в стиле Duolingo

Переосмысление страницы результата: вместо стены markdown-текста — визуальная цепочка этапов, по которой пользователь движется.

### Как выглядит
```
🟢 Этап 1: Основы         ← пройден, раскрыт
    ↓
🔵 Этап 2: Практика       ← текущий
    ↓
⚪ Этап 3: Проект         ← заблокирован
    ↓
🎯 Итог
```

### Что нужно реализовать (~120 строк кода)
1. **Парсер этапов** — regex по заголовкам `## 📍 Этап N:` из markdown-ответа GigaChat (~25 строк)
2. **Новый UI результата** — карточки/expander на каждый этап, кнопка "Отметить пройденным" (~70 строк)
3. **Прогресс-бар** — X из N этапов вверху страницы (~5 строк)
4. **Экран завершения** — поздравление когда все этапы отмечены (~15 строк)
5. **Практические задания внутри этапов** — GigaChat генерирует задание, пользователь вставляет решение, получает фидбек (+50 строк)

### Открытые вопросы перед реализацией
- Этапы блокируются последовательно (как Duolingo) или все доступны сразу?
- Прогресс сбрасывается при "Начать заново"?
- JSON или парсинг markdown — как получать структуру от GigaChat?

### Оценка
~570 строк суммарно по всему проекту. Реалистично за один день работы.

## Геймификация

### Реализуемо быстро (session_state, без БД)
- **Прогресс по этапам** — чекбоксы "Этап пройден" под каждым блоком трека + полоса прогресса (0% → 100%) вверху страницы результата.
- **Экран завершения** — когда все этапы отмечены, показывается поздравление с достигнутым уровнем.
- **Бейджи уровня** — по результатам диагностики показывается карточка: 🔰 Новичок / ⚡ Практик / 🏆 Эксперт. Визуально мотивирует.

### Реализуемо за день (в связке с GigaChat)
- **Практические задания** — GigaChat генерирует одно задание на каждый этап, пользователь вставляет решение, получает фидбек. Challenge → reward loop.

### Требует хранилища (файл / БД)
- **Стрики** — серия дней подряд, когда пользователь учился. Нужно хранить дату последнего визита между сессиями.
- **История треков** — личный кабинет, где хранятся все построенные треки и прогресс по ним.
- **Лидерборд** — сравнение с другими пользователями. Требует авторизации.

# Идеи для развития Прогрессоров

## 1. Монетизация

Freemium модель: бесплатно 1 активный трек, платно — безлимит + приоритетная генерация.
- Подписка ~300–500 ₽/мес через Telegram Stars или ЮKassa
- Таблица `subscriptions` в Supabase, проверка лимита перед построением нового трека

## 2. Расширение источников

- Яндекс Практикум, Skillbox, Coursera — парсинг публичных каталогов
- Habr статьи по теме (заготовка `habr.py` уже есть)
- GitHub — репозитории с учебными материалами и шпаргалками

## 3. Социальный слой

- Публичные треки — поделиться своим маршрутом по ссылке
- Менторы — опытный пользователь берёт ученика
- Лидерборд по пройденным этапам
- Новые таблицы в Supabase + хендлеры в боте

## 4. Геймификация

- Стрики: серии дней подряд (хранить `last_active_date`)
- XP и уровни за пройденные этапы
- Бейджи достижений в Mini App

## 5. Веб-версия

- Полноценный сайт вместо только Telegram Mini App
- Авторизация через Telegram Login Widget
- Стек: Next.js + существующий FastAPI бэкенд

## 6. Улучшение рекомендаций

- Собирать данные: какие этапы лайкают, упрощают, пропускают
- Через 3–6 месяцев обучить модель на реальных оценках пользователей
- Превращает продукт из LLM-обёртки в настоящую рекомендательную систему

## 7. B2B — корпоративное обучение

- Компания создаёт треки для сотрудников
- HR видит дашборд прогресса команды
- Наиболее денежный вектор, требует отдельного продукта

## 8. Ускорение бота — Pre-fetch этапов

Сейчас при открытии каждого этапа: LLM-вызов `_get_stepik_params` + Stepik API (1-3 HTTP запроса).

**Оптимизация 2 — Pre-fetch Stepik params для всех этапов:**
После генерации трека запускать в фоне параллельные LLM-вызовы `_get_stepik_params` для ВСЕХ этапов сразу (через `asyncio.gather`). Добавить функцию `_prefetch_stepik_params(stages, state)`, вызывать из `build_track` после `_send_stage(0)`.

**Оптимизация 3 — Pre-fetch следующего этапа:**
- Кэшировать результаты Stepik-поиска в `stage["stepik_courses"]`
- В `_send_stage`: если кэш есть и этап не модифицирован → использовать кэш, иначе искать и кэшировать
- После отправки этапа N → запускать `_prefetch_next_stage(stages, idx+1, state)` в фоне
- В `stage_hard`/`stage_easy`: сбрасывать `stages[idx]["stepik_courses"] = None`

Итог: этап 0 — как сейчас, этапы 1+ — открываются мгновенно.

## Технический стек для масштабирования

Текущий стек (aiogram + FastAPI + Supabase) выдержит ~10k пользователей. Далее:
- PostgreSQL read replicas
- Очередь задач (Celery / ARQ) для фоновой генерации
- Нативное мобильное приложение (Flutter или React Native)

## Приоритет

1. Монетизация → деньги на развитие
2. Геймификация → удержание пользователей
3. Расширение источников → качество контента

## Технический долг

Проблемы выявленные при code review, требуют решения по мере роста проекта.

**Критичные (решить до публичного запуска):**
- Включить RLS в Supabase — сейчас любой с anon ключом может читать данные всех пользователей
- Добавить UNIQUE constraint на `user_id` в `user_tracks` — убрать костыль PATCH-then-POST

**Значимые (решить при росте аудитории):**
- Написать тесты — хотя бы integration тесты для критичных флоу (онбординг, генерация трека)
- Перейти на `supabase-py` вместо самописного urllib клиента
- Добавить rate limiting — защита от спама запросами к LLM
- Обрезать промпты перед отправкой в LLM — защита от выхода за context window при длинных `liked_stages`

**Мелкие:**
- `_HEADERS_BASE` в `supabase_client.py` вычисляется при импорте — если `SUPABASE_KEY` не задан, ключ будет пустым навсегда
- `WEBHOOK_SECRET` имеет хардкоженный дефолт — лучше падать с ошибкой если не задан в env
